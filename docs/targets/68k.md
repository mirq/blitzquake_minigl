# 68060 target guide (MiniGL dispatch)

Target: **68060-class Amiga (e.g. PiStorm) running the PiStorm SDK
`minigl.library` dispatch client**. No Warp3D, `mgl.library`,
`mglasm.library` or PPC code is involved.

- Build: `Makefile.GCCAmiga68k_MiniGLDispatch` (see
  [building.md](../building.md#68060--pistorm-minigl-dispatch)).
- Output: `m68k_gcc_perf/glquake/glquake68k_060_perf`, an Amiga HUNK
  executable.
- Target-specific build notes: [`glquake/README.MinGLDispatch.md`](../../glquake/README.MinGLDispatch.md).

## What "dispatch client" changes versus the 2002 port

The classic 2002 Amiga build called `mgl.library` in-process and used
`miniglext.c` to write vertices **directly** into MiniGL's shared vertex
buffer (`mglTV23fv`, `mglTV23fvLM`, `mglMtexTV23fv` with `MGLVertex`
writes). The PiStorm dispatch client only exposes the Minigl dispatch ABI;
under `MINIGL_DISPATCH_CLIENT` those helpers are emulated with ordinary GL
calls:

```c
/* glquake/miniglext.c, dispatch branch */
glMultiTexCoord2fARB(GL_TEXTURE0_ARB, v[3], v[4]);
glMultiTexCoord2fARB(GL_TEXTURE1_ARB, v[5], v[6]);
glVertex3f(v[0], v[1], v[2]);
```

This is more portable (and required by the dispatch sandbox) but costs one
call per vertex. It is the reason a whole class of batching experiments was
tried — and why they failed: on this stack the per-call dispatch is cheap,
and the frontend's per-vertex work dominates. See
[../decisions/REJECTED_PATHS.md](../decisions/REJECTED_PATHS.md).

Renderer differences selected by `MINIGL_DISPATCH_CLIENT`
(`gl_texsort`, lightmap format, alpha fills, error drains) are listed in
[../architecture/renderer.md](../architecture/renderer.md#compile-time-renderer-variants).

## 68060 constraints

- **Alignment**: the 68060 faults on unaligned word/long accesses. All
  structures shared with assembly and all hunk data must be naturally
  aligned. The hunk allocator returns 16-byte-aligned blocks; keep it that
  way when adding allocations.
- **Memory pools**: chip RAM is scarce and used for audio DMA; renderer data
  lives in fast RAM via the Quake hunk. Do not add per-frame allocations or
  large static buffers; the map hunk is sized once per map.
- **Instruction cache**: keep hot loops small; `-O3` plus `FASTBOPS`
  (`gl_model.h`) is the intended configuration.
- `OPTIMIZE_060` selects float-or-int alias vertex pointer paths in
  `gl_rmain.c` (the 060 has an FPU).
- The maintained 68k build compiles only three assembly modules
  (`common68k.o`, `sys_amiga68k.o`, `in_amigamouse68k.o`) through
  `vasmm68k_mot -Fhunk -m68060`; all renderer hot paths are C.

## Assembly and generated offset headers

The legacy 68k builds (`Makefile.Amiga68k*`, `Makefile.GCCAmiga68k_MGL`)
assemble many `.s` renderer/rasterizer files that read field offsets from a
generated header (`quakedef68k.i` / `glquakedef68k.i`). The generator and the
rules are documented in
[building.md](../building.md#assembly-offset-headers).

Rules when touching structures used by assembly:

1. The generated headers are produced by the **target** compiler's
   `offsetof`/`sizeof`, so never hand-edit or cross-use them.
2. If you change a struct in `gl_model.h`, `r_shared.h`, `d_local.h`,
   `quakedef.h` or similar, check which `.s` files include the matching
   `.i` and rebuild/regenerate for each affected target.
3. Both 68k and PPC are big-endian, so no byte swapping is involved — only
   layout/alignment.
4. The maintained dispatch builds do not use these headers; do not break
   them for the legacy builds by reordering a struct without checking.

## Performance notes specific to the 68k target

- The accepted baseline for the old `mgl.library` 68k path is 3.002 fps on
  `demo1` at 640×480×32 (68060/50 MHz, RV280). See
  [history/WORKSTREAM_A_RENDERER_PLAN.md](../performance/history/WORKSTREAM_A_RENDERER_PLAN.md).
- The generic client-array experiment is **rejected**: replacing one
  seven-float `glpoly_t` with one generic array draw was 5.4% slower. Details
  and the future-direction note are in
  [history/STEP4_REJECTED_GENERIC_ARRAY_PATH.md](../performance/history/STEP4_REJECTED_GENERIC_ARRAY_PATH.md).
- Profile before optimizing: use `-benchmarklog`, `host_speeds 1` and the
  MiniGL diagnostics (`MINIGL_PERF_DIAGNOSTICS`) exposed by this build.
- Keep one variable per benchmark series and take repeated cold-boot samples;
  1–9% first-run-after-boot variance was measured.

## Running

```text
Stack 1048576
glquake68k_gcc -width 320 -height 240 -bpp 32 -windowmode
```

The large stack is required when launching from a shell/script; direct
asynchronous launch helpers may not apply the executable's requested stack.
Add `-condebug` for `id1/qconsole.log` logging. See
[README.MinGLDispatch.md](../../glquake/README.MinGLDispatch.md) for the
launch helper (`launch_minigl`).
